# DailyFlow V1.1 开发原则

- **日期**：2026-08-28
- **基线**：`v1.0.0`（已发布并跨机验证）
- **状态**：已批准（用户确认，作为 V1.1 开发依据）

---

## 1. V1.1 重点方向

1. **灵活性** —— 配置、布局、习惯适配更灵活
2. **操作手感** —— 交互反馈、流畅度、细节体验
3. **信息获取** —— 更快看到所需信息
4. **反馈与统计** —— 数据沉淀与回顾

## 2. V1.1 明确不开发

- ❌ AI 助手
- ❌ 云同步
- ❌ 用户账号
- ❌ 服务器
- ❌ 付费服务
- ❌ 多用户
- ❌ 在线数据库

## 3. DailyFlow 保持的产品形态

- **本地优先**（Local-first）
- **SQLite** 本地存储
- **无需服务器**
- **个人使用**
- **联网功能仅在需要时联网**

## 4. 开发约束

- 不删除 V1.0 现有功能
- 不破坏数据库 Schema（如需演进，走新增迁移，绝不改已有迁移）
- 每次功能改动保持测试覆盖（Vitest）
- 保持 V1.0 建立的发布链路：`npm.cmd run tauri build` → NSIS 安装器（自带 WebView2 固定运行时）
