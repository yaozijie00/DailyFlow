# DailyFlow 产品机制调研与改造建议

调研日期：2026-10-09（Asia/Shanghai）。范围：专注、长期任务与甘特图、任务详情、收集箱、外观以及可选模块。选取 8 个产品、16 份官方资料。本文区分已验证的产品机制与针对 DailyFlow 的设计判断；未登录产品账户，也未做竞品完整交互测试，因此不把宣传文案当作效率或专注效果的证明。

## 结论

建议围绕“收集 → 澄清与安排 → 执行 → 回顾”组织 DailyFlow。甘特图是长期计划的另一种视图；任务详情是统一的编辑入口；专注页只呈现本次行动与计时状态。新增页面之前，先让这几个入口共享一致的任务语义。

优先处理三个问题：让专注页回答“现在做什么、还要多久、接下来怎么办”；让长期计划回答“阶段、日期、进展、下一步”；让任务详情把主要内容与属性分开。以上是设计建议，需要通过 DailyFlow 的原型与使用测试验证效果。

## 面向 DailyFlow 的具体决策

### 1. 专注：把计时作为独立能力

以下是设计方案，并非竞品事实。以 Sunsama 的单任务中心和 Session 的可选意图为启发。

| 状态 | 主区显示 | 主操作 | 次要信息 |
| --- | --- | --- | --- |
| 待开始 | 可选任务 / 可选本轮意图；计时模式与时长 | 开始专注 | 上次设置、今日累计、最近任务 |
| 进行中 | 当前意图、任务名或“自由专注”、清晰计时 | 暂停 | 结束、快速记录想法、当前任务的下一步 |
| 已暂停 | 已计入专注的时长、暂停状态 | 继续 | 结束并保存 |
| 本轮结束 | 本轮实际时长、可选完成与下一步 | 保存记录 | 开始休息、继续下一轮 |
| 休息中 | 休息剩余时长与状态 | 结束休息 | 延长休息、返回待开始 |

推荐实现约束：

- `taskId` 可空，`intention` 可空；没有任务也可开始并保存到专注历史，不生成“占位任务”。结束后可选择关联现有任务或从意图创建新任务。
- “番茄”用固定工作段与休息提示；“正计时”从零开始，用户自主结束。倒计时结束代表本轮结束，不自动代表任务完成。
- 一个全局活动计时会话；切换页面不停止计时。主页面或小窗显示相同状态，避免同时运行多个相互矛盾的计时器。
- 暂停时长与休息时长不计入有效专注；结束可保存未完成的一轮。明确标识中断与提前结束，不把记录静默丢弃。
- 专注时不展示大块统计、排行榜、全量历史和任务配置；统计放到结束回顾或可折叠区域。
- 快速收集采用一句文本输入，保存到 Inbox 后回到当前会话。用户不必在专注途中决定长期层级。
- 计时依据时间戳和暂停片段恢复；重启后询问恢复或结束上一轮，而非把关闭时间全部算作专注。实际恢复规则需跟现有存储与跨端能力匹配。

自由计时不等同于付费方案中的“免费计时”；本文推荐的“无任务”指没有任务关联的会话。

### 2. 长期任务：先确定对象，再添加甘特图

建议默认采用“项目 → 阶段 → 任务”，更小的执行点使用清单项。阶段可以是项目内分组，避免新增具有重复语义的独立实体；具体映射需结合现有数据模型决定。

必须明确三种关系：父子代表工作拆解，阶段代表分组，依赖代表先后约束。依赖不能仅通过缩进表达，也不能把父子关系自动当成依赖关系。

建议甘特图首版包含：

1. 左侧固定任务树，右侧日 / 周 / 月时间轴；今天线、开始与结束日期、状态、展开与收起。
2. 项目概要显示目标、下一里程碑、下一可执行任务。无日期的任务进入“未排期”区域，不消失，也不默认虚构时间条。
3. 点击条目打开统一详情；拖动条目改变开始日期，拖动边缘改变范围。键盘与表单也能编辑同样字段。
4. 里程碑以单日节点表示，可由阶段完成或手动标记完成；需把具体规则写清。
5. 父级日期显示“子项汇总”或“手动设置”来源，避免用户编辑后发生看不见的回滚。
6. 依赖首轮可先提供“被阻塞 / 阻塞谁”信息和连线；自动重排、关键路径、工作日历、基线放到后续迭代。

同一个任务的“日历跨度”“预计投入时长”“实际专注时长”“硬截止日期”应分开。跨两周不代表需要工作 14 天；两个时段也不代表两个任务。进度应明确为清单完成率、子任务完成率或投入时长，不把这些指标混为一谈。

### 3. 详情：阅读与编辑共享同一结构

参考 Todoist 的内容与属性分区，结合 Linear 的连续预览。推荐桌面常驻侧面板用于快速查看与编辑，提供展开到完整详情；小屏用完整页面。高风险操作保留显式入口。

内容顺序：所属路径 → 标题与完成状态 → 目标 / 说明 → 下一步或子任务 → 笔记。属性顺序：状态、计划日期范围、截止日期、优先级、项目 / 阶段、预计时长。依赖、标签、记录、附件和历史按需展开。

普通任务与长期任务共用标题、说明、属性和保存反馈；项目详情可增加阶段与甘特预览，计时记录详情展示本轮意图与时长。避免分别维护多个互相不一致的任务弹窗。

主要按钮最多保留“开始专注”与必要的完成动作；复制、归档、删除等进入菜单。直接编辑字段时显示保存中 / 已保存 / 保存失败，关闭面板不会丢失未保存输入；支持撤销与恢复。

### 4. 收集箱：支持逐条澄清

借鉴 Things 的“先收集、后安排”，建议 Inbox 默认列表密度高于项目卡片页。每行只显示标题、来源或简短预览、收集时间和必要标识。支持多行粘贴、键盘连续处理与批量归属。

处理面板回答四个问题：这是什么；是否需要行动；下一步是什么；是否现在安排。动作建议为：安排今天、设置日期、移入项目、拆为项目、暂存、归档。删除保留撤销。

“澄清完成”与“任务完成”分开。事项从收集箱移走代表获得归属，不表示已经执行；默认不让已安排事项继续积压在 Inbox。空状态展示“记录一个想法”入口以及一句工作方法提示即可。

### 5. 外观：让用户选择气质，保留可学习的操作

以 TickTick 官方外观配置为机制依据，DailyFlow 的具体样式是设计提案。建议先做 4 套语义 token 主题，而不是每套重写页面：

| 风格 | 表面与强调色 | 适合情境 |
| --- | --- | --- |
| 清透 | 浅灰白、蓝色强调、紧凑但有呼吸感 | 工作与大量任务处理 |
| 纸感 | 暖白、低饱和橄榄色、柔和边界 | 阅读与每日规划 |
| 深夜 | 深灰、克制的青绿色、清晰状态对比 | 暗环境与长期专注 |
| 森林 | 中性底色、自然绿与细微暖色 | 喜欢柔和视觉的日常使用 |

颜色主题、亮暗模式、内容密度、字体大小和减少动效分别设置。操作位置、任务状态语义与警告色保持统一。首先保证现有页面都使用语义颜色，再添加风格；背景图片和装饰不能降低任务文字与甘特连线可读性。

## 是否新增其他模块

以下优先级为针对当前问题的判断，不代表竞品功能的普遍有效性。优先复用现有页面，不自动增加导航项。

| 候选模块 | 优先级 | 最小版本 | 理由与边界 |
| --- | --- | --- | --- |
| 今日规划 | P1，核心体验稳定后 | 从未安排事项中选今日 1–3 个重点，查看预计总时长，加入今天 | 连接长期计划与当下执行；机制参考 Akiflow Rituals。时长只提供建议，不强制填满一天。 |
| 每日 / 每周回顾 | P1 | 完成事项、计划与实际投入、延期任务、下一步，允许补充一句笔记 | 帮用户判断计划是否可执行；机制参考 Akiflow。复盘不强制弹出，不制造每天评分压力。 |
| 下一步与阻塞提示 | P1，作为项目能力 | 项目里显示可开始的下一任务、阻塞原因和到期节点 | 直接解决长期任务缺乏指导；属于甘特与项目摘要的一部分，无需独立模块。 |
| 轻量时间块安排 | P2 | 把同一任务安排为多个可编辑执行时段 | 机制参考 Sunsama Timeboxing。若 DailyFlow 已有日历，优先改进其任务联动；避免维护第二份任务。 |
| 目标 / OKR | P2，待用户需求证据 | 为项目增加成功标准、目标日期 | 先验证项目目标字段是否足够，再考虑跨项目目标层级。 |
| 知识库 / 笔记 | P2，优先完善现有笔记 | 任务或项目说明、相关资料链接 | Things 证明任务上下文可直接承载笔记；不需要因此立即新建第二个笔记产品。 |
| 强制阻断应用与网站 | P3 | 仅在桌面支持与用户需求明确后评估 | Session 有该机制，但技术边界、权限和跨平台成本独立于 UI 整理。 |
| 团队协作 / 资源管理 / 完整关键路径 | 暂不新增 | 保留数据扩展空间 | 当前反馈集中于个人任务和专注；复杂团队字段会提高已有页面整理成本。 |

建议验证顺序：专注开始与保存是否顺畅 → 普通任务能否在统一详情完成编辑 → 长期项目能否明确下一步与日期 → 收集事项能否批量澄清 → 再评估日规划、周回顾和时间块。判断标准可包括：从进入专注到计时开始的步骤数、详情编辑失败 / 丢失率、未排期任务可见率、收集箱澄清步骤数；“专注效果更好”需要用户测试，不能仅凭更简洁的界面断言。
