# DailyFlow 时间轴交互控制器设计

## 目标

在不改变用户可见行为、数据语义和视觉样式的前提下，把时间轴的跨窗口拖拽副作用从渲染组件中移出，使后续多日视图、任务依赖和更多拖放来源可以独立扩展。

## 方案选择

采用按交互域拆分的小型 Hook：

- `useTimelineExternalDrops` 管理任务列表拖入、便签拖入、Ghost 预览和全局监听清理。
- `useTimelineCanvasInteractions` 管理空白拖拽创建、任务移动、上下边缘调整、横向换栏和工作范围分割线。
- `Timeline.tsx` 保留状态读取、布局计算和 JSX 组合，继续作为时间轴页面的装配层。

没有采用“只提取纯函数”，因为主要复杂度来自监听器生命周期和交互状态；也没有采用单个巨型 Hook，因为它会把原来的大文件问题转移到另一个文件。

## 数据流与边界

两个 Hook 不直接读取 Zustand。`Timeline.tsx` 通过参数传入任务、便签、配置和命令回调，Hook 只返回预览状态与事件处理函数。这样状态库、持久化实现和时间轴交互不会互相锁死。

`useTimelineCanvasInteractions` 通过 `getLaneLayout(taskId)` 获取最新分栏，不拥有布局算法。用户换栏偏好仍只在当前会话存活，并通过返回的 `getPreferredLane` 参与 `computeLanes`。

所有写操作仍在鼠标松开时发生。移动到时间轴外只清空计划时间；调整边缘同步预计时长；便签转换仍使用同一个 undo 批次。

## 错误与清理

Hook 卸载、窗口失焦或 Escape 取消时清空预览并移除监听器。持久化失败继续由现有 Store 负责提示，控制器不显示虚假的成功状态。外部拖入的监听器在 mouseup 时同步移除，避免下一次拖动复用旧闭包。

## 验证

- 为画布控制器覆盖空白创建、调整时长、移出时间轴和取消清理。
- 为外部拖入保留现有纯函数与转换测试，并通过 TypeScript 检查 Hook 接口。
- 运行完整 Vitest、生产构建、真实 Tauri E2E 和桌面开发启动检查。
- 验收后 `Timeline.tsx` 目标降至 400 行以内。
