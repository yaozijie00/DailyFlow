# DailyFlow 体验改造方案

日期：2026-10-09。状态：首轮核心改造已实施到应用源码，详见[实施记录与验证结果](dailyflow-experience-implementation-2026-10-09.md)。以下保留原调研阶段的审查、方案和原型验证快照。

交付：[8 个产品的竞品调研](dailyflow-product-research-2026-10-09.md)、本文的本地审查与实施方案，以及[四页面可操作概念原型](prototypes/dailyflow-experience-prototype.html)。原型可双击打开，不需要联网；采用虚构数据，刷新会恢复，所有操作不访问 DailyFlow 数据库。

原调研轮按“调研、形成具体方案并展示”推进，当时没有改变正式应用代码、数据库、安装包或发布版本。用户随后授权按计划实施，当前源码已完成首轮核心改造与隔离 Tauri 验证。产品仍是本地优先、个人使用的 Windows 桌面应用，沿用仓库既有开发原则。用户没有指定长期事项属于学习、创作还是项目交付，因此方案同时照顾有期限和无期限的事项。

## 1. 建议的产品方向

把 DailyFlow 组织成一条连续路径：**收集 → 澄清 → 长期规划 → 今日安排 → 专注执行 → 回顾调整**。

甘特图帮助理解阶段与日期，统一详情负责查看与编辑，专注页围绕本轮行动组织。新增风格共享这些结构。对照研究并不能证明某套设计“最优”；这里的选择优先解决用户已指出的问题，效果通过真实任务试用验证。

| 用户需求 | 推荐结果 | 关键边界 |
| --- | --- | --- |
| 长期任务可视化 | 长期工作台中加入甘特视图；阶段、任务与里程碑可追踪；持续展示下一步 | 同一个任务在甘特、今日与详情中使用同一个 ID |
| 任务详情更适合查看与编辑 | 统一内容组件；标题、说明和子任务在主区，安排与归属在属性区 | 面板、展开视图和窄窗页面共享字段与保存行为 |
| 专注重构 | 待开始、运行、暂停、结束、休息与异常恢复各有明确主操作 | 计时结束与任务完成分别处理 |
| 无任务计时 | 与“关联任务”并列的直接入口 | 当前代码已有能力，主要是提高可见性与完善记录归属 |
| 更多外观 | 保留经典和玻璃；新增纸感、森林、石墨 | 风格、亮暗、密度和动效分别控制 |
| 收集箱优化 | 紧凑列表 + 明确的逐条/批量整理入口 | 收集事项移出不等于任务已完成 |
| 其他模块 | 优先完善已有日规划、周复盘和下一步提示 | 不因竞品存在某模块就增加顶层导航 |

## 2. 当前项目审查：已有能力与真正缺口

以下依据当前源码静态审查。历史设计文档用于了解沿革，不作为“当前已实现”的证据。本轮没有启动现有 Tauri 应用，也没有测量当前界面的实际认知负荷。

| 审查对象 | 当前证据 | 含义与改造 |
| --- | --- | --- |
| 长期入口 | `src/pages/Goals.tsx` 使用 `PlanningWorkspace`；`PlanningWorkspace.tsx` 提供工作台、全部事项、复盘和周容量 | 已有规划与回顾，不必新建同义模块 |
| 多套长期界面 | 当前入口使用 `PlanningDetail`，阶段管理切到 `PhasePlan`；另有 `LongTermPlanDetail` / `LongTermDashboard` 实现 | 按实际引用先画入口图，再统一详情与阶段导航；不能仅因存在旧文件就认定它仍是活动页面 |
| 计划与项目 | `planningWorkspaceService.ts` 使用 `plan:<id>` / `project:<id>` 共享读模型；任务归组优先 `projectId`，其次 `goalId` | UI 可统一工作台，但不能把两者当作完全相同的存储实体 |
| 阶段 | `schema.ts` 的 `long_term_phases` 属于 goal，包含状态、估时与手动进度，没有日历起止日期 | 阶段甘特不能直接复用已有日期字段；需要新增迁移或明确使用子项汇总 |
| 任务日期 | `tasks` 只有日安排 `scheduledDate`、时间块 `plannedStart/plannedEnd` 与估时 `estimatedDuration` | 多日计划跨度不能覆盖今日时间块；估时也不能当作跨度 |
| 无任务计时 | `FocusWorkspace.tsx` 的“开始无关联专注”调用 `start(null)`；`focus/types.ts` 的 `taskId` 允许空 | 应改为清晰的“无任务计时”入口；无需另造一套计时器 |
| 专注推荐 | `TaskPicker` 按当前时间块、今日高优先级、今日任务、绑定下一步、更新时间排序 | 已有规则，可显示推荐原因；查询目前没有排除有子项的父任务，正式改造需统一“可执行任务”筛选 |
| 专注可靠性 | `FocusRecord` 有实际秒数、暂停、恢复、checkpoint 和 revision；已有 controller、休息 store 与 Rust 执行模块 | 重构显示层时保留现有状态源、恢复与多窗同步，不回退成前端自增秒数 |
| 任务详情重复操作 | `TaskDetail.tsx` 的延期区之前与底部操作区都渲染 `StartFocusButton` | 同一个主操作出现两次，先去重，再统一位置 |
| 查看与编辑分离 | 详情中部分备注可内联编辑，其他字段用 `openEdit` 打开 `TaskFormModal`；详情同时堆叠计划、备注、子任务、统计、延期与危险操作 | 应将常用字段直接编辑；完整表单保留给创建与集中修改，复用字段组件 |
| 收集箱 | `Today.tsx` 中收集箱位于任务左栏底部，限制在 `max-h-32` 或 `max-h-44`；`NoteItem` 支持拖拽，文字双击编辑，操作较依赖 hover | 大量事项下空间不足，操作发现成本高；保留快速收集，新增展开整理视图与可见按钮 |
| 外观 | `theme.ts` 目前为 system/light/dark/glass；已有语义色；设置中另有 standard/compact/focus 密度 | 新风格应扩展 token 与设置，而不是再把密度塞进主题枚举 |

最值得优先验证的假设：用户困扰主要来自信息与操作的竞争，以及同一对象在不同页面呈现不一致。仅加更多卡片、图表或导航可能进一步增加选择负担。

## 3. 长期任务与甘特图

### 3.1 先固定术语与归属

界面中用“长期事项”统称计划和项目，保留类型差异。第一版沿用现有关系：

- 长期计划 → 可选阶段 → 执行任务 → 子任务。
- 项目 → 执行任务 → 子任务；项目可以关联长期目标。阶段当前只属于长期计划，不默认为项目也已有阶段能力。
- 准备清单用于准备条件；里程碑用于成果节点；依赖用于先后约束。三者都不自动当作普通父任务。
- 未拆分任务可以执行；存在有效子任务的父任务默认作为汇总项，从开始专注和自动推荐中排除。是否允许直接专注父任务需作为明确产品选择，不能各页自行判断。

保留现有 `projectId` 与 `goalId` 的关联数据。一个任务在执行容量与专注统计中按现有 owner 规则只计一次；在目标的总体汇总中可以展示项目贡献，但要注明“包含下属项目”，不能再次叠加直接统计。成果自动进度只聚合有效叶任务，排除取消项与父项；未建立基准显示“未建立进度”，而不是 0% 已落后。

把下一步尽量绑定真实 `taskId`。尚未成形的文字仍可暂存，用户点击“安排”时通过现有服务生成一个任务并记录来源，后续不重复生成。

### 3.2 甘特图布局

借鉴 [ClickUp 的任务树、日期条与里程碑](https://help.clickup.com/hc/en-us/articles/6310249474967-Create-and-share-a-Gantt-view)，适配个人桌面场景：

1. 顶部：事项名称、下一步、“加入今天”与“开始专注”。操作对象是执行任务，不能对汇总阶段直接开任务计时。
2. 视图切换：工作台 / 甘特 / 列表 / 复盘，沿用当前工作台的数据。首版优先周视图与月跨度，日粒度用于缩放；不增加单独“甘特模块”。
3. 左侧：固定任务树，名称、展开按钮与必要状态。右侧：日期刻度、今天线、任务范围、阶段汇总条、里程碑。
4. 次区：未排期任务、本周承诺/容量、下一节点。无日期事项留在未排期区，不为了绘图自动填入今天。
5. 点击任务打开统一详情。日期可通过表单修改；拖动与拉伸为快捷方式，提供预览与撤销。窄窗图表在自身区域内横向滚动，详情转换为完整页面。

首版提供日期、阶段展开、里程碑、未排期区、状态与下一步。依赖连线与自动重排后置；自动重排将来默认关闭，启用时预览受影响任务、容量和冲突，并允许整体撤销。父子关系不自动代表依赖。

### 3.3 四种时间必须分开

| 信息 | 用途 | 当前存储 / 建议 |
| --- | --- | --- |
| 多日计划范围 | 甘特中预计在哪段日历日期推进 | 新增 `task_planning_ranges`：taskId 唯一、开始日、结束日，可两者均缺省 |
| 日执行安排 | 哪天实际做、当天几点做 | 继续使用 `scheduledDate`、`plannedStart/plannedEnd` |
| 预计投入 | 需要多少工作分钟 | 保留 `estimatedDuration`，明确单位秒；UI 统一换算 |
| 实际投入 | 专注产生的有效时长 | 继续使用统一专注记录与现有统计口径 |

`scheduledDate` 目前允许空字符串作为未排期值，且数据库列 NOT NULL。读取层可以规范化为未排期，不能在没有迁移时直接写 null。

计划的 `deadline`、项目的 `targetDate` 当前是目标日期。首版保留其语义；若以后需要“不可延期的硬截止”，新增独立字段并显示差异，不能静默把现有目标日期重新解释。

阶段默认汇总子项起止日，标注“由子任务汇总”；没有已排期子项则显示“未排期”。如需要手动阶段范围，新增覆盖字段并显示来源与恢复汇总操作。里程碑建议使用轻量独立记录，保存 `itemKey`、可选阶段、名称、节点日期和完成状态；第一版手动完成，不自动按任意任务勾选推断已达成果。

日期校验在服务层完成：起止需成对、结束不早于开始、使用本地 YYYY-MM-DD；日期范围不会偷偷覆盖当天时间块。调整整个阶段时必须预览移动哪些子项；仅修改目标日期不自动挪动执行任务。

### 3.4 进度要能解释

保留当前按任务、估时加权、手动三种口径，并显示来源。默认按有效叶任务完成数；全部叶任务都有可靠估时后，才可选择估时加权。手动进度明确标识，并可恢复自动。

时间投入条与成果条分别呈现。日历已过去 50%、已投入 50% 时间，都不能直接显示为完成 50% 成果。没有成果基准时，不根据日期推算“落后 X%”。逾期提示说明是某个节点日期已过；容量提示说明超出多少承诺。

## 4. 统一任务详情

参考 [Todoist 的内容主区与属性侧区](https://www.todoist.com/help/todoist/features/use-the-task-view-to-manage-tasks-in-todoist-eDeRDO0C)。DailyFlow 采用“统一内容、三种承载”方案：

- 今日与甘特点击任务：可持续编辑的详情面板，不因修改日期立刻关闭。
- 面板展开：完整详情，适合长说明、阶段与子任务。
- 窄窗口：单页详情，固定返回和主操作。返回后恢复原视图与滚动位置。

默认内容顺序：所属路径 → 标题/状态 → 主操作 → 说明与完成标准 → 子任务/执行清单 → 折叠投入记录。

属性区默认仅显示日安排、计划范围（已启用甘特时）、预计投入、优先级与所属事项/阶段。重复、分类、来源、创建时间和扩展操作进入“更多属性”。取消、删除、归档进入更多操作菜单，保留撤销或当前确认语义。

“开始专注”只出现一次；完成与开始是不同动作。标题、说明和属性可直接编辑，页面显示“保存中 / 已保存 / 保存失败”。文本输入支持草稿、失焦提交、Esc 取消；失败保留输入并允许重试；日期或所属事项变更涉及其他对象时用显式应用操作。

工程上提取 `TaskDetailContent`、共享字段与草稿保存逻辑，让 `TaskDetail`、`TaskFormModal` 的编辑部分与甘特详情复用。通过 taskId 读取完整数据，不依赖“今天任务列表里刚好有这个任务”。复用现有 `useOverlayFocus` 等焦点管理，关闭后焦点返回原任务。

保存过程中用户切换任务或收到 Mini 变更时，草稿按 taskId 隔离。旧请求返回不能覆盖新任务；检测版本冲突后保留草稿，给出重新读取或应用修改。不得用无反馈的乐观关闭掩盖错误。

## 5. 专注页：指导动作，降低开始成本

设计取舍参考 [Sunsama 单任务专注视图](https://help.sunsama.com/docs/usage-guides/focus-mode/)、[Session 的意图与上下文笔记](https://www.stayinsession.com/learn/getting-started-with-session-pomodoro-app)。意图与结束反思可选，不能成为开始计时的必填门槛。

| 状态 | 首要信息 | 主要操作 | 按需出现 |
| --- | --- | --- | --- |
| 待开始 | 关联任务 / 无任务计时并列；推荐一个可执行动作及理由 | 开始 | 模式、目标时长、可选本轮意图、搜索 |
| 运行 | 当前意图、任务名、清楚的计时数值 | 暂停 | 结束、随手收集、任务上下文 |
| 暂停 | 暂停状态、已有效投入；说明暂停不计入 | 继续 | 结束并记录 |
| 目标达到 | 已投入、目标达到提示 | 记录本轮或继续 | 开始休息；不自动勾选任务 |
| 结束 | 有效投入、可选进展和下一步 | 保存投入 | 同时完成任务（仅有任务关联时） |
| 休息 | 独立休息计时 | 结束休息 | 延长、跳过、再来一轮 |
| 异常恢复 | 最近已确认投入和离开时间 | 按现有规则确认恢复 | 排除离开时间、纳入或丢弃，沿用现有明确提示 |

待开始页面默认只强调一个推荐任务，显示“当前时间块 / 今日重点 / 本周下一步”等依据。搜索全部任务改为选择操作中的弹层，不与当前动作持续竞争注意力。

无任务计时不生成占位任务，保存到专注历史与总投入中，归入“未关联投入”，不能自动计入某个计划的成果或项目容量。结束时后关联任务作为第二阶段能力：需原子更新来源与统计，避免两处重复计时；初版可直接保存未关联记录。

计时方式用熟悉的三个名称：正计时、倒计时、番茄钟。“无任务”是关联方式，不是第四种计时模式。倒计时展示剩余时间和已投入；达到目标后提示并显示超出时长。番茄钟采用工作段和休息提示，复用现有设置，是否自动开始下一段由用户选择。

运行态采用中间计时与主按钮，任务说明和随手记按需展开。可展示“当前阶段 / 本轮动作 / 下一步”的短路径；它描述行动上下文，不按秒钟自动推进任务完成。圆环表示本轮时间进度，正计时不制造没有目标的百分比。

沿用 `useFocusStore`、controller、Rust `focus.rs` 与现有跨窗通知。DOM 的每秒刷新局部限制在计时和进度标记，不让整页和甘特树每秒重渲染。对主窗、全局控制条与 Mini 的同一会话保持一致。重构后继续通过恢复、重复操作、revision、暂停、结束保存失败的现有检查。

## 6. 收集箱

借鉴 [Things 的先收集、后澄清](https://culturedcode.com/things/support/articles/6378414/)；具体取舍如下：

- 今日保留小型捕获入口和未整理数量，点击“整理收集箱”打开更宽的面板。先扩展现有入口，无需新增顶层导航。
- 行内默认只显示名称、可选预览、收集时间、选择框和明确“整理”按钮。详情编辑支持单击与键盘，不依赖双击或 hover 才发现。
- 逐条整理：安排为今日/指定日期的任务、加入已有长期事项、由多步骤想法建立计划/项目、保存笔记、暂存或归档。
- 选择目标时实际选择计划/项目；选择日期时注明该日安排，不强制分配时间段。批量处理显示条数和目标。
- 已转换条目记录来源与目标 taskId/itemKey，可从历史跳转。转换创建与原条目标记保持一致，快速连续点击只转换一次。
- 转换可撤销；失败保持未整理状态与输入，不出现一条想法生成两个任务。大批量转换预览后执行，可报告部分失败而不隐藏错误。
- 收集条目“已安排”和任务“已完成”分别显示；默认收集箱只看未整理，已处理放折叠历史。

现有拖拽继续作为快捷方式，所有转换都有按钮入口。新念头在专注时快速送入收集箱，自动回到当前计时，不把所有念头塞进当前任务备注。

## 7. 外观与共同交互规范

保留默认经典靛蓝和现有玻璃。新增纸感（低饱和暖中性色）、森林（自然绿）、石墨（灰蓝、紧凑边界）。原型预览经典、纸感、森林、石墨，每种可切换亮暗。

配置建议为 `appearanceStyle` + 现有 `themeMode` + 现有 `defaultLayoutMode`，分别控制气质、亮暗、密度。旧版本没有 appearanceStyle 时使用经典。玻璃保留既有模式语义，第一版限定经典玻璃组合；若以后拆成材质设置，提供显式设置迁移，不能让旧 glass 用户丢失外观。

不加载远程字体，沿用本地中文与 Segoe UI 字体栈。统一 4/8 间距节奏、正文 14–16px、辅助文字至少 12px、计时数字等宽。桌面常用操作提供充足点击面积，重要按钮至少 44px 高。警告、错误、已完成通过文字/图标与颜色共同表达。

所有风格对比度独立检查；普通文字达到 4.5:1，关键图形与控件边界达到 3:1。键盘焦点可见；图表条形可聚焦；日期调整、排序和移动有非拖拽路径。动画用于解释展开/移动/保存，不做装饰性连续动效；遵从减少动效设置。

窗口验收至少覆盖 820/900/1100/1440 宽度与系统缩放。甘特局部横向滚动允许，整页横向溢出不允许。详情在窄窗重排；长中文标题、已归档任务、空列表都能完成操作。

## 8. 是否添加其他模块

| 候选能力 | 判断 | 最小落地方式 |
| --- | --- | --- |
| 每日规划 | 值得完善，P1 | 在已有今日页选择少量重点、展示预计投入和容量；数量可调整 |
| 周复盘 | 已有能力，优先优化，P1 | 当前长期复盘里贯通成果、投入、改期与下一步，减少重复入口 |
| 下一步与阻塞 | 值得完善，P1 | 作为长期详情与甘特摘要，提供原因与可执行任务，不独立开模块 |
| 专注中随手收集 | 值得添加，P1 | 小输入框调用现有收集服务；不打断会话 |
| 多次执行时段 | 需求验证后，P2 | 现有任务只存一组时间块；若要同一任务多个时段，再新增执行时段实体，而非复制任务 |
| 习惯追踪 | 先验证，P2 | 优先利用当前重复任务，区分习惯打卡是否需要独立数据 |
| 深度笔记/知识库 | 暂缓 | 先完善任务/项目说明与已有笔记去处 |
| 强制屏蔽应用/网站 | 暂缓 | 有明确需求后单独评估桌面权限与可靠性 |
| AI 调度、账号、云同步、团队资源 | 本轮不纳入 | 与当前本地个人形态和既有开发边界不匹配；需另有用户指令 |

原则：先连接已有模块，再用使用证据决定扩张。比如用户能在当前复盘看清进度后，就无需再增加一个“仪表盘”页面。

## 9. 分阶段实施与验证

不按猜测给工期；每阶段有可交付结果与门槛。

| 阶段 | 工作范围与主要入口 | 可验收结果 |
| --- | --- | --- |
| 0：语义与入口统一 | 核对任务 owner、叶任务、日期、进度、下一步；绘制实际页面引用；明确旧视图去留 | 用同一组真实任务在今日、长期、详情、统计得到一致归属与计数 |
| 1：详情和专注 | `TaskDetail`/`TaskFormModal` 共享编辑；重构 `FocusWorkspace` 显示层；提高无任务入口可见性 | 用户连续修改标题/日期/说明而不用跳转；无任务能立即开始、暂停、保存；无重复开始按钮 |
| 2：甘特首版 | 新增日期范围/里程碑迁移与仓库、甘特读模型、条形布局、日期编辑、详情联动 | 有日期任务可编辑，未排期可见；调整不覆盖日时间块；父项不重复计数；修改与撤销一致 |
| 3：收集与外观 | 收集箱展开整理、来源追踪、批量转换；appearanceStyle 语义 token 与设置迁移 | 各条都有去处与恢复路径；风格在四核心页面和 Mini 同步，重启保留偏好 |
| 4：试用迭代 | 少量真实长期任务进行完整路径试用，优化已有规划/复盘；决定依赖/多时段需求 | 记录观察结果与具体卡点，再选择扩展能力 |

甘特渲染建议沿用 React、现有样式 token 和 SVG 依赖线（如以后需要）；甘特时间条本身用可聚焦 DOM，便于日期编辑与可读列表。现有 Recharts 保留统计用途。第三方甘特库是否采用，需另做小型可行性验证：中文、本地运行、主题、可访问性、许可、拖拽事件和包体；本轮没有调查库版本，不指定未经验证的库。

正式实施新增数据库字段只用新增迁移，不改已有迁移。优先通过现有 Service/Repository/UndoManager/DataVersion，不建立第二份任务或第二个专注 store。旧数据补齐必须幂等；无日期不猜测跨度；转换关系和计时重新关联必须事务化或有明确恢复策略。

关键行为检查：

1. 专注：无任务/关联叶任务 × 正计时/倒计时/番茄；暂停不累计；结束不默认完成任务；恢复与 Mini 控制一致；保存失败可重试。
2. 详情：快速切换任务、输入法组合、长标题、无日期、已删除项、异步保存失败与跨窗更新；草稿不串任务。
3. 甘特：单日/跨月/闰日/未排期、阶段日期来源、取消与归档项、拖动/表单一致性、整体撤销、日时间块不变。
4. 统计：任务与父项不重复，项目与上级目标汇总不叠加，未关联投入不凭空归属，手动进度与时间记录分开。
5. 收集：重复点击只转换一次；目标创建失败、标记失败与部分批量失败可恢复；撤销后不会生成孤立副本。
6. 外观：经典/纸感/森林/石墨/现有玻璃，亮暗与紧凑密度，820–1440 宽度、系统缩放、键盘与减少动效。

有逻辑与迁移改动时运行相关 Vitest、类型检查与生产构建，再运行必要的跨窗/Tauri QA；研究和原型文件不需要假称正式应用已通过这些检查。

试用任务建议：安排一个有 3 个阶段的长期事项；从收集箱整理 5 条事项；连续编辑 3 个任务；无任务计时后保存；中途暂停再恢复；周复盘调整下一步。记录完成率、操作次数、回退点、错误与用户是否能解释进度口径。结果是评估依据，不预先许诺百分比提升。

## 10. 原型能力与验证边界

原型涵盖甘特/列表切换、日期调整表单、详情标题/说明/日安排/估时编辑、任务完成、关联或无任务计时、暂停/继续、结束备注与投入历史、收集与批量整理、四套风格亮暗切换。

它展示布局和基本状态，不包含真实推荐查询、甘特拖拽与依赖自动重排、数据库保存、跨窗同步、系统通知、番茄自动循环、休息倒计时或异常恢复；收集箱目标转换只模拟移出列表，尚未创建真实示例任务/项目。计时示例使用时间戳计算，但不替代正式应用的可靠性机制。

正式方案和竞品报告存在抽象层级的区别：竞品报告提出通用“项目 → 阶段 → 任务”方向；本文按 DailyFlow 当前模型保留计划与项目，阶段首版只属于计划。外观候选在原型中收敛为经典、纸感、森林、石墨，亮暗单独切换。后续以本文的本地映射为实现依据。

实际验证：使用 Playwright 的无界面 Chromium 读取本地原型，9 条流程通过（甘特日期修改、详情标题修改、无任务计时、暂停/恢复、保存备注与下一步、关联任务计时、取消结束并恢复、收集、批量整理）。4 页面 × 4 风格 × 2 亮暗 × 4 宽度（375/820/1100/1440）共 128 组整页横向溢出检查通过；未捕获 JavaScript 页面错误。此矩阵检查布局尺寸，不代表已完成人工可用性或每个控件对比度认证。另人工查看了甘特、运行中的专注与详情截图。

验证记录与截图位于本机 `artifacts/experience-concept-2026-10-09/`（仓库已有忽略规则，不纳入源码）。浏览器运行需要沙箱外启动，自动审批允许后完成；未访问真实数据库。正式应用的 Vitest、Tauri 和发布构建本轮没有运行。
