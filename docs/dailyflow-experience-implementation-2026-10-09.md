竞品研究建议的连续路径为“收集 → 澄清 → 长期规划 → 今日安排 → 专注执行 → 回顾调整”。本轮保留已有工作台、周容量与复盘入口，添加专注中随手收集；没有增加重复的顶层模块。习惯、知识库、应用屏蔽、AI 调度及云同步继续按原方案暂缓。

## 统一后的数据规则

- 项目和长期计划继续保留原类型及 ID。执行归属优先项目，其次长期计划；阶段仍属于长期计划。
- 有有效子任务的父项作为汇总项；专注推荐、原生开始与补录均拒绝将它当作执行任务。今日执行完成率、长期工作台执行汇总、已完成任务查询与 Mini 进度排除父项和取消项。创建数量仍表示创建的对象数量。
- 甘特父项和阶段的范围由执行叶任务汇总。多层子任务按整棵树计算；父子阶段不一致时，甘特将子树随根任务展示在同一阶段。阶段自动进度同样按该树的叶任务计算，手动进度保留。
- 多日范围独立于 `scheduledDate` 和当天时间块。修改甘特日期不覆盖今日安排；详情修改日安排会清空原当天时间块，并给出提示。无日期数据保持未排期，不自动猜测多日跨度。
- 标题、说明和常用属性使用显式保存，便于把相关修改一起提交。详情保存、甘特日期与里程碑编辑检查版本，拒绝覆盖已有更新；失败输入保留。
- 收集项转换为任务通过一条 SQLite INSERT 及触发器同时完成来源占用、任务创建、来源状态与链接写入，防止跨连接或重复点击产生副本。恢复来源会同时移除转换任务；已有投入、专注记录或子任务时阻止恢复。恢复 / 撤销保留原 ID、来源与长期日期。

## 复现方法

普通检查在项目根目录运行：

```powershell
npm.cmd test
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml
```

真实 Tauri QA 需要 Python Playwright，以及单独运行的开发应用。先在一个终端设置隔离目录并启动；以下环境变量只影响当前终端，数据目录覆盖仅在 Rust debug 构建生效：

```powershell
$taskQaRoot = Join-Path (Get-Location) 'artifacts/experience-implementation'
New-Item -ItemType Directory -Force -Path $taskQaRoot | Out-Null
$env:DAILYFLOW_QA_DATA_DIR = Join-Path $taskQaRoot 'focus-native-qa'
$env:LOCALAPPDATA = Join-Path $taskQaRoot 'local'
npx.cmd tauri dev --config src-tauri/tauri.experience-qa.conf.json
```

随后在另一个项目根目录终端依次运行：

```powershell
python scripts/qa_experience.py
python scripts/qa_experience_mini.py
python scripts/qa_experience_layout.py
```

脚本确认当前数据库位于隔离 QA 目录后才执行操作。核心流程每次使用唯一测试名称；数据库核对使用只读 SQLite 连接。Mini 验证会短暂显示独立 QA 窗口。开发应用需运行至界面初始化完成；结束后可在启动终端按 Ctrl+C。

## 首版边界与试用

本轮对应方案阶段 0–3 的核心实现。依赖线、自动顺延、资源调度及同一任务多个执行时段未纳入首版。阶段目前使用执行树汇总日期，里程碑归属于计划 / 项目；旧数据已有日安排时可显示单日条，没有日安排时明确显示未排期。

阶段 4 的真实任务试用仍需要使用反馈：建议安排一个多阶段长期事项、整理数条收集项、编辑任务，再做一次无任务计时和周复盘，观察阶段位置、主要操作与进度是否容易理解。自动验证已确认数据与操作链路，没有预先宣称某种布局对所有使用场景最优。
