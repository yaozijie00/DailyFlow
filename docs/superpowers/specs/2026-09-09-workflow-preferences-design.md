# Workflow 扩展偏好与兼容性设计

## 目标

让内置 Workflow 成为首个真实使用 `ctx.storage` 的扩展，并让扩展清单在加载前具备稳定 ID、语义版本和 API 版本校验。

## 用户行为

设置页新增“Workflow · 偏好”分组，提供“创建后自动打开编辑器”开关。默认开启，保持当前行为；关闭后创建成功停留在 Workflow 列表，适合连续建立多个流程。

偏好由 Workflow 扩展自行管理。首次初始化先建立 v1 的 `open-created` 键，再由 v2 迁移为 `preferences` 对象并删除旧键，用真实升级链验证宿主迁移协议。

## 模块边界

- `preferences.ts`：初始化、迁移、读取与保存，不依赖 React。
- `Settings.tsx`：扩展贡献的设置 UI，仅调用偏好模块。
- `Page.tsx`：创建成功时读取当前偏好，不直接访问存储。
- `index.ts`：声明能力、执行初始化、注册清理器并贡献设置页。

## 清单兼容性

- ID 必须是小写反向域名格式，段内允许连字符。
- 扩展版本必须是 SemVer 2.0 形式。
- API 版本必须是正安全整数。
- 清单合法但 API 版本与宿主不一致时，记录明确的加载诊断。

## 验收

- 新库最终处于偏好版本 2，旧键已删除。
- 已有 v1 用户值迁移后保持不变。
- 设置开关持久化成功后才更新界面状态，失败时显示错误。
- 创建后是否打开编辑器与偏好一致。
- 非法清单与 API 不兼容均有测试。
