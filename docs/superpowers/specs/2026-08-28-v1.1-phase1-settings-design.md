# DailyFlow V1.1 Phase 1 设计文档 — Settings 与基础操作灵活性

- **日期**：2026-08-28
- **基线**：`v1.0.0`（已发布并跨机验证）
- **状态**：已批准（用户确认设计方案，含 Schema 迁移方案）
- **关联**：`docs/V1.1-dev-principles.md`

---

## 1. 目标

提升 Settings 与基础操作的灵活性，包含五块：

1. 快捷键设置（可自定义、防重复、冲突提示、恢复默认）
2. 任务分类管理（增/改/删/排序，删除时任务不丢失）
3. 存储位置设置（数据/缓存/备份目录，路径校验，重启生效）
4. 番茄钟设置扩展（专注/短休/长休/长休间隔）
5. Settings 分组 UI（General / Pomodoro / Shortcuts / Categories / Storage / Data）

**明确不做（本阶段）**：新闻/统计/时间轴页面的快捷键（页面不存在）、番茄钟休息计时循环、全局热键（仅应用内）、目录选择插件（零新插件）、数据库自动迁移。

## 2. Settings 分组 UI

- Settings 页改为横向 Tab 导航：**General / Pomodoro / Shortcuts / Categories / Storage / Data**
- General：时间轴设置（开始/结束/吸附粒度，自 V1.0 原样迁移）
- Pomodoro：专注时长 + 短休 + 长休 + 长休间隔
- Data：现有备份/恢复 + 版本号显示（原样迁移）
- 其余见下各节

## 3. 快捷键（Shortcuts）

### 3.1 存储

`settings` 表新键 `shortcuts`，值为 JSON 字符串：

```json
{ "open_dailyflow": "Ctrl+Shift+D", "create_task": "Ctrl+Shift+T", ... }
```

**无 Schema 变更**。空字符串 = 该动作禁用快捷键。

### 3.2 动作与默认值（仅现有页面/操作）

| 动作 key | 默认值 | 行为 |
|---|---|---|
| `open_dailyflow` | `Ctrl+Shift+D` | 唤起并聚焦窗口（show + setFocus + unminimize） |
| `create_task` | `Ctrl+Shift+T` | 切换到今日页并打开新建任务弹窗（弹窗挂在今日页） |
| `pomodoro_toggle` | `Ctrl+Space` | 运行中→暂停；暂停→继续；空闲→toast 提示 |
| `complete_task` | `Ctrl+Shift+Enter` | 完成当前选中任务；未选中→toast 提示 |
| `open_today` | `Ctrl+1` | 切到今日页 |
| `open_focus` | `Ctrl+2` | 切到专注页 |
| `open_settings` | `Ctrl+3` | 切到设置页 |

### 3.3 纯函数库 `src/lib/shortcuts.ts`

- `eventToCombo(e: KeyboardEvent): string` —— 规范化组合键，修饰键顺序 `Ctrl+Alt+Shift+Meta`，主键：字母大写、空格→`Space`、其余用 `e.key` 原值
- `formatCombo(combo): string` —— 展示用格式化
- `findDuplicateCombo(combo, actions: Record<string,string>): string | null` —— 返回占用该组合的动作名
- `DEFAULT_SHORTCUTS` —— 上述默认表；`isDefaultShortcuts()`
- `isEditableTarget(el: EventTarget | null): boolean` —— input/textarea/select/contenteditable 内不触发

### 3.4 挂载与冲突处理

- App 级 `keydown` 监听：忽略 `e.repeat`、忽略编辑控件内按键
- 匹配到动作后 `preventDefault()` 并分发
- 冲突：保存时若新组合已被其它动作占用 → 阻止保存并提示「该快捷键已被「X」使用」
- UI 提供「恢复默认值」按钮

### 3.5 测试

`src/lib/shortcuts.test.ts`：eventToCombo 各修饰键组合、Space/字母规范化、重复检测、默认值唯一性、isEditableTarget。

## 4. 分类管理（Categories）

### 4.1 Schema 迁移（已批准）

新增迁移 `0001_category_sort_order.sql`：

```sql
ALTER TABLE `categories` ADD COLUMN `sort_order` integer NOT NULL DEFAULT 0;
--> statement-breakpoint
UPDATE `categories` SET `sort_order` = `id`;
```

Drizzle schema 增加：

```ts
sortOrder: integer("sort_order").notNull().default(0),
```

现有行按 `id` 回填（等价于插入顺序），V1.0 数据无损。迁移由 `runMigrations` 在测试内存库自动执行。

### 4.2 Repository / Service / Store

- `CategoryRepository.findAll()`：`ORDER BY sort_order ASC, id ASC`
- `create(name)`：`sort_order = (SELECT COALESCE(MAX(sort_order),0)+1 FROM categories)`
- `reorder(orderedIds: number[])`：按传入顺序批量写 `sort_order = 下标`
- `delete(id)`：直接删除；外键 `ON DELETE SET NULL`（`PRAGMA foreign_keys=ON`）自动把任务 `category_id` 置 NULL，**任务不丢失**
- `CategoryService`：findAll / create / rename / delete / reorder
- `taskStore` 新增分类 actions（增/改/删/排序），完成后 `load()` 刷新

### 4.3 UI（Settings → Categories Tab）

分类列表（显示名称 + ↑↓ 调序 + 改名 + 删除确认）+ 底部新增输入框。

### 4.4 测试

`categoryRepository.test.ts` 扩展：排序正确、新增取 MAX+1、reorder 生效、删除分类后任务 `category_id` 为 NULL。

## 5. 存储位置（Storage）

### 5.1 架构

数据目录需在数据库打开前确定 → 路径**存库外配置文件**：

```
%APPDATA%\com.dailyflow.desktop\storage.json
```

```json
{ "dataDir": "", "cacheDir": "", "backupDir": "" }
```

空串 = 用默认值。Rust 命令读取时机在数据库打开之前（前端先 invoke 取路径再开库），无鸡生蛋问题。

### 5.2 Rust 变更（`src-tauri/src/lib.rs`）

- 新命令 `get_storage_paths(app)` → `{ dataDir, cacheDir, backupDir }`（解析默认值：dataDir=`%LOCALAPPDATA%\DailyFlow`，backupDir=`dataDir\backups`，cacheDir=空）
- 新命令 `set_storage_paths(app, dataDir, cacheDir, backupDir)`：
  1. 非空路径必须是**绝对路径**，否则拒绝
  2. `fs::create_dir_all` 创建（允许目录不存在）
  3. 写探针文件验证可写，随后删除
  4. 写 `storage.json`
- `dailyflow_data_dir()` / `resolve_backups_dir()` 改为读取配置（命令签名增加 `app: AppHandle`，Tauri 自动注入，前端调用不变）
- cacheDir 仅存储（当前无缓存使用场景）

### 5.3 数据不自动迁移

- 新数据目录首次启动会**创建全新数据库**（自动跑迁移）
- 旧数据保留原目录不动；UI 明示：可手动复制 `dailyflow.db` 或用备份恢复
- 保存后提示：**「新的数据位置将在重新启动DailyFlow后生效」**

### 5.4 UI（Settings → Storage Tab）

三个路径输入框 + 保存；内联校验错误提示；成功提示重启生效。

### 5.5 测试

`src/lib/storagePaths.ts`（前端校验纯函数：绝对路径/规范化）+ 单测；Rust 校验手测。

## 6. Pomodoro 设置
