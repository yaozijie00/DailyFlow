# DailyFlow Workflow 重设计规格

**日期：** 2026-09-09  
**状态：** 已确认  
**范围：** Workflow 扩展完整重设计；DailyFlow 本体在现有结构上做一致性优化

## 1. 背景与目标

DailyFlow 本体已经具备今日规划、任务、时间轴、目标、统计、设置和扩展能力。本轮不重做本体的信息架构，重点提升 Workflow 的实际使用价值：把重复的项目初始化、目录创建、文件生成和工作环境启动固化为可复用模板。

本轮目标：

1. 让用户无需理解流程画布，也能从模板库快速完成自动化操作。
2. 让用户能够通过可视化编辑器创建和维护自己的线性 Workflow。
3. 建立节点注册、变量解析、操作预览、权限检查和运行记录等稳定边界。
4. 保证现有 Workflow 数据能够迁移并继续使用。
5. 为后续条件分支、循环、并行、Git、日历和第三方应用节点保留扩展能力。

## 2. 范围边界

### 2.1 DailyFlow 本体

保留现有一级导航、页面结构和核心操作路径。本体只进行以下优化：

- 统一颜色、字号、间距、圆角、阴影、图标和控件状态。
- 优化任务卡片、时间轴、表单、弹窗、空状态和统计图表的视觉层级。
- 补齐加载、保存、失败、撤销和危险操作反馈。
- 提升键盘焦点、点击区域、文字对比度和减少动效支持。
- 在现有 Today 与任务入口中增加 Workflow 快速启动能力，不改变页面职责。

### 2.2 Workflow 扩展

Workflow 的信息架构、模板体验、编辑器、节点体系、运行器和运行记录均纳入重设计。

第一阶段不支持条件分支、循环和并行执行。线性执行模型继续作为稳定内核，但节点接口和连线端口模型必须允许后续增加控制流能力。

## 3. 信息架构

Workflow 扩展包含三个固定视图：

| 视图 | 默认内容 | 主要操作 |
| --- | --- | --- |
| 模板库 | 内置模板、我的模板、收藏、最近使用、分类与搜索 | 运行、创建、复制、收藏、编辑 |
| 编辑器 | 节点库、画布、属性面板、验证面板 | 配置变量、编排节点、试运行、保存、运行 |
| 运行中心 | 运行中、等待确认、失败、已完成记录 | 查看进度、确认、取消、重试、打开结果 |

进入扩展时默认显示模板库。复杂画布只在创建或编辑模板时出现。

## 4. 核心用户流程

### 4.1 从模板运行

1. 用户从模板库、Today 快捷入口或任务操作菜单选择模板。
2. 运行器展示模板说明、所需能力和变量表单。
3. 用户填写变量；系统实时校验类型、必填项和路径。
4. 用户进入预览，系统生成逐步执行计划与文件树差异。
5. 冲突项明确显示为创建、跳过、覆盖、重命名或失败。
6. 用户确认后开始执行。
7. 运行面板展示当前节点、已完成步骤、输出和错误。
8. 完成后提供打开目标目录、查看日志和关联任务等结果操作。

### 4.2 创建模板

1. 用户选择空白模板或复制已有模板。
2. 填写名称、说明、分类、标签和变量定义。
3. 在画布中添加并连接节点。
4. 编辑器持续显示结构错误、字段错误和权限警告。
5. “试运行”仅生成执行计划，不产生系统副作用。
6. 保存生成新模板版本；正式运行始终绑定当时的版本快照。

### 4.3 从任务启动

任务菜单提供“运行 Workflow”。运行实例记录 `taskId`，完成后按模板规则更新或完成关联任务。任务更新失败时不得把运行错误地标记为完成。

## 5. 模板与变量

模板由元数据、变量定义、节点图和执行设置组成。

第一阶段变量类型：

- 单行文本
- 多行文本
- 数字
- 开关
- 单选列表
- 日期
- 文件路径
- 文件夹路径

每个变量具有稳定键、显示名称、说明、类型、必填状态、默认值和可选校验规则。节点字符串配置使用 `{{variable_name}}` 引用变量。

变量解析遵循以下规则：

- 未定义变量属于阻断错误。
- 必填变量为空属于阻断错误。
- 路径变量在预览前完成规范化，但保留用户可读形式。
- 运行实例保存解析后的变量快照，不读取模板后续修改后的默认值。
- “最近使用值”仅对用户明确允许记忆的非敏感变量保存。

## 6. 编辑器设计

编辑器采用固定三栏结构：

- 左侧节点库：按流程控制、文件系统、系统操作和 DailyFlow 分类。
- 中间流程画布：编排、连线、框选、拖拽、缩放和自动排列。
- 右侧属性面板：编辑当前节点配置、变量引用、冲突策略和错误策略。
- 底部验证面板：集中显示阻断错误、警告和最近试运行结果。

顶部工具栏提供返回、模板名称、保存状态、撤销、重做、试运行、保存和正式运行。

编辑器必须支持：

- 节点复制、删除和多选。
- 删除节点时同步清理连线。
- 未保存状态和离开提醒。
- 保存失败后保留本地草稿。
- 点击验证问题定位到节点和字段。
- 自动排列后仍可撤销。
- 键盘操作和可见焦点。

## 7. 节点体系

### 7.1 第一阶段节点

**流程控制**

- 开始
- 人工步骤
- 等待确认
- 完成

**文件系统**

- 创建文件夹
- 批量创建目录结构
- 创建文本文件
- 从模板复制文件
- 复制文件或目录

**系统操作**

- 打开文件
- 打开文件夹
- 打开网址
- 启动应用
- 执行受控命令

**DailyFlow**

- 创建任务
- 更新任务状态
- 记录运行结果到关联任务
- 完成关联任务

### 7.2 节点注册接口

节点不再由编辑器、验证器和执行器分别写死判断，而是通过统一定义注册：

```ts
interface WorkflowNodeDefinition<TConfig = Record<string, unknown>> {
  type: string;
  version: number;
  category: string;
  title: string;
  capabilities: WorkflowCapability[];
  ports: WorkflowNodePortDefinition[];
  configSchema: WorkflowNodeConfigSchema<TConfig>;
  validate(config: TConfig, context: ValidationContext): ValidationIssue[];
  preview(config: TConfig, context: PreviewContext): Promise<PlannedEffect[]>;
  execute(config: TConfig, context: ExecutionContext): Promise<NodeResult>;
}
```

注册表负责节点发现、版本迁移、能力聚合和重复类型检测。UI 通过配置模式生成通用字段；只有复杂节点提供独立属性编辑器。

## 8. 执行模型

第一阶段继续使用单起点、单终点、无循环的线性链。执行分为四步：

1. **解析：** 冻结模板版本和变量快照。
2. **验证：** 校验图结构、节点配置、路径和权限。
3. **预览：** 每个节点生成结构化 `PlannedEffect`，不产生副作用。
4. **执行：** 按顺序执行节点并写入步骤级结果。

运行状态保留现有 `pending`、`running`、`paused`、`awaiting-confirm`、`completed`、`failed` 和 `cancelled`，新增步骤级状态与输出记录。重试从失败节点开始，已经成功且声明为幂等的节点不重复执行。

每次运行保存：

- Workflow 与结构版本
- 变量快照
- 关联任务
- 节点进入、完成和失败时间
- 结构化输出与用户可读摘要
- 实际创建或修改的路径
- 错误类型、错误信息和可重试性

## 9. 权限与文件安全

能力按文件读取、文件写入、打开路径、启动程序和执行命令分别声明。运行前汇总展示模板需要的能力。

文件写入规则：

- 默认冲突策略为“失败”，禁止静默覆盖。
- 节点可显式选择失败、跳过、覆盖或自动重命名。
- 预览必须显示目标绝对路径与冲突结果。
- 文件操作记录本次实际创建的路径。
- 失败清理只删除本次新建且执行后未再次变化的内容。
- 对已有内容的覆盖必须单独确认，不承诺自动还原无法安全恢复的外部修改。

命令节点规则：

- 默认关闭，用户需在 Workflow 设置中主动启用。
- 可执行程序、参数数组和工作目录分别存储，不拼接整段 shell 字符串。
- 运行前完整显示解析后的程序、参数和目录。
- 不记录用户标记为敏感的变量明文。
- 退出码、标准输出和标准错误按大小上限保存。

## 10. 数据与迁移

Workflow 增加独立 `schemaVersion`，并为变量定义、运行快照和步骤记录增加专属存储。

现有节点迁移关系：

| 现有类型 | 新类型 |
| --- | --- |
| `goal` | `core.start` |
| `action` | `core.manual-step` |
| `checkpoint` | `core.checkpoint` |
| `finish` | `core.finish` |
| `app` | `system.launch-app` |
| `file` | `system.open-file` |
| `folder` | `system.open-folder` |

迁移在读取时生成候选结果，通过验证后一次性写入。迁移失败时保留原数据并展示可恢复错误，不产生部分迁移的 Workflow。

## 11. 视觉与交互规范

Workflow 使用 DailyFlow 现有设计语言的优化版：中性色界面、蓝色主要操作、语义色状态和轻量微交互。

- 节点颜色用于辅助分类，类型仍由图标和文字表达。
- 节点卡片只显示名称、类型、摘要和状态，不承载复杂表单。
- 所有图标按钮具有可访问名称和至少 44×44 px 的点击区域。
- 普通文字对比度不低于 4.5:1。
- 动效控制在 150–240 ms，并尊重减少动态效果设置。
- 800 px 宽度下编辑器切换为画布与属性抽屉；模板库使用单列布局。
- 加载期间预留稳定尺寸，避免画布和列表跳动。

## 12. 错误处理

错误分为四类：

| 类型 | 处理方式 |
| --- | --- |
| 结构错误 | 阻止保存或运行，定位到节点或连线 |
| 配置错误 | 在字段附近显示，保留已输入内容 |
| 权限错误 | 显示缺失能力和开启路径，不自动扩大权限 |
| 执行错误 | 停在失败节点，保存日志，提供安全重试或结束运行 |

页面级异常由扩展错误边界隔离，不影响 DailyFlow 本体。存储失败时保留编辑器草稿，并允许复制原始配置用于恢复。

## 13. 首批内置模板

- 创建通用项目目录
- 创建前端项目资料目录
- 创建设计项目目录
- 每日工作启动
- 每日复盘与归档
- 打开固定工作环境

内置模板只读，用户编辑时创建个人副本。模板不依赖固定盘符，路径由变量提供。

## 14. 测试与验收

### 14.1 自动化测试

- 节点注册、重复类型和版本迁移测试。
- 变量解析、缺失变量、路径规范化和敏感值测试。
- 预览与执行结果一致性测试。
- 文件冲突四种策略测试。
- 运行状态转换、暂停、取消、失败和重试测试。
- 旧 Workflow 数据迁移与失败回滚测试。
- 模板库、变量表单、编辑器验证和运行面板交互测试。
- Tauri 文件创建、应用启动和命令执行集成测试。

### 14.2 人工验收

- 新用户能在两分钟内从内置模板创建项目目录。
- 用户无需打开编辑器即可完成模板运行。
- 执行前能清楚确认所有将创建或修改的路径。
- 任一失败节点均能看到原因、已完成步骤和下一步操作。
- 原有 Workflow 迁移后能够正常打开、保存和运行。
- 800×600 至 1440×900 视口无横向页面溢出。
- 键盘能够完成模板搜索、变量填写、预览与运行。

## 15. 成功指标

- 内置“创建通用项目目录”模板从进入 Workflow 到开始执行不超过四个主要操作。
- 有效变量输入后，执行预览在本地常规目录结构下 300 ms 内完成。
- 运行记录能够解释每个节点的状态和输出，不出现只有通用错误提示的失败。
- 新增一种普通节点不需要修改模板库、画布核心、验证器分派或运行器分派代码。
- 本体已有任务、时间轴、目标和统计流程保持兼容。
